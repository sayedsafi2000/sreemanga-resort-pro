# Deploying Pina Vista on Coolify (Docker Compose)

One Coolify resource runs the whole stack from this repository: **Postgres + API (`server`) +
admin panel (`admin`) + public website (`web`)**. Every push to `main` redeploys automatically once
the GitHub App webhook is enabled. Nothing has to be typed into a `.env` by hand except the email
provider — database password, JWT secret and the URLs are generated by Coolify.

## 1. Create the resource

1. Coolify → your Project → **+ New Resource → Docker Compose** (under *Git based*).
2. Source: **Private Repository (with GitHub App)** → pick this repo, branch `main`.
3. Leave **Base Directory** `/` and **Docker Compose Location** `/docker-compose.yml`.
4. Coolify parses the file and shows four services: `db`, `server`, `admin`, `web`.

## 2. Domains (before the first deploy)

Each service that declares `SERVICE_FQDN_*` gets a domain field in Coolify. Set them to your real
domains (https, no trailing slash). The container ports are already encoded in the compose file,
so you only type the URL:

| Service  | Example domain                | What it serves                     |
|----------|-------------------------------|------------------------------------|
| `web`    | `https://pinavista.com`       | Public website (Next.js, :3002)    |
| `admin`  | `https://admin.pinavista.com` | Staff admin panel (nginx, :80)     |
| `server` | `https://api.pinavista.com`   | REST API (Express, :8000)          |

DNS: create **A records** for the three hostnames pointing at the Coolify server's IP. Traefik
issues Let's Encrypt certificates automatically once DNS resolves.

The admin and web containers read the API URL **at start-up** (`API_URL`, `PUBLIC_API_URL`), so you
can change the API domain later in Coolify and just redeploy — no code change needed.

## 3. Environment variables

Open the resource → **Environment Variables**. Coolify has already generated:

- `SERVICE_USER_POSTGRES`, `SERVICE_PASSWORD_POSTGRES` — database credentials (keep them; the
  volume is tied to them)
- `SERVICE_PASSWORD_64_JWT` — JWT signing secret
- `SERVICE_URL_SERVER` / `SERVICE_URL_ADMIN` / `SERVICE_URL_WEB` — derived from the domains above

Fill in **one** email transport (guests cannot finish the OTP step without it):

| Variable | Notes |
|----------|-------|
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS` | any SMTP provider (Gmail app password, Zoho, Brevo SMTP, …) |
| `RESEND_API_KEY` | or Resend |
| `BREVO_API_KEY`, `BREVO_EMAIL` | or Brevo API |
| `EMAIL_FROM` | e.g. `Pina Vista <noreply@pinavista.com>` |

Optional: `STRIPE_SECRET_KEY` + `STRIPE_WEBHOOK_SECRET` (card payments; webhook URL is
`https://api.<domain>/api/public/stripe/webhook`), `CORS_ORIGIN` (defaults to the admin + web
URLs), `API_RATE_LIMIT_PER_MIN` (default 600 per signed-in user), `POSTGRES_DB`.

## 4. Deploy and first login

Click **Deploy**. Build takes a few minutes the first time (three images). On first boot the API
runs `prisma db push`, and because the database is empty it seeds the demo accounts, rooms and
settings. Log in at the admin domain with `admin@pinavista.com / Admin@12345`
(see `docs/ROLES_AND_USERS.md`), then **change every seeded password** (Admin → User Accounts)
and fill Settings (resort name, phone, payment accounts, invoice note).

The seed never runs again while the database has users, so nothing you change in the admin panel
is overwritten on redeploys. To force it once: set `RUN_SEED=true`, redeploy, then remove it.

## 5. Auto deploy

Resource → **General → Auto Deploy** on. With the GitHub App source Coolify installs the webhook
itself; every push to `main` rebuilds the changed images and rolls them out.

## 6. Day-to-day

- **Logs / terminal:** each service has *Logs* and *Terminal* in Coolify.
  Manual seed: `npx tsx prisma/seed.ts` in the `server` terminal.
- **Database backup:** `db` terminal → `pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" > /tmp/backup.sql`
  (or schedule Coolify's backup on the `pgdata` volume). Restoring: `psql -U "$POSTGRES_USER" "$POSTGRES_DB" < backup.sql`.
- **Schema changes** are applied automatically at container start (`prisma db push`).
- **Run the same stack locally** (needs Docker):
  `cp .env.compose.example .env && docker compose -f docker-compose.yml -f docker-compose.local.yml --env-file .env up --build`
  → web `http://localhost:3002`, admin `http://localhost:3003`, API `http://localhost:8000`.

## Troubleshooting

| Symptom | Check |
|---------|-------|
| Admin shows *Network Error* on login | `server` domain set? Browser console → request URL should be `https://api.<domain>/api/...`. `CORS_ORIGIN` must include the admin URL (default does). |
| 502 on a domain right after deploy | Container still starting (health check `start_period` is 40 s for API/web). See *Logs*. |
| Guests never get the OTP email | No email transport configured, or `SMTP_*` wrong — API logs show the send failure. |
| `Too many requests` (429) | Rate limit hit; raise `API_RATE_LIMIT_PER_MIN` or `AUTH_RATE_LIMIT_PER_15MIN`. |
| Website shows default text/rooms | API unreachable from the web container — `INTERNAL_API_URL` is `http://server:8000/api/public`; check the `server` health. |
